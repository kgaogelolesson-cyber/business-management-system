# Test Plan - Business Management System

## 1. How testing was done

| Level | What | Who/when | Where results are |
|---|---|---|---|
| Automated self-checks | 14 console programs (`*Check`) call the real services and database, create "Check..." rows, and clean up afterwards | Run by `AllChecks` | `docs/testing/automated-results.md` and `automated-details.txt` (generated by running the program; not hand-written) |
| Volume check | 3,000 customers, 1,500 products, 1,300 orders for one customer; list limits and speed (< 3,000 ms per call) | `VolumeCheck` (part of `AllChecks`) | same files |
| Data integrity check | Read-only audit of the whole database (integrity, foreign keys, totals, stock, admin exists, hashes) | `DataIntegrityCheck` (part of `AllChecks`) | same files |
| Manual test cases | Section 4 below. Someone clicks through the real screens | You (the tester) | Fill in the **Actual** and **Status** columns yourself |

**How to run the automated checks:** in NetBeans, right-click `src/main/java/com/bms/AllChecks.java` -> *Run File*. Close DB Browser first. Expected last lines: `ALL SUITES PASSED.` The program exits with code 1 if any check fails.

**Honesty note:** the Actual/Status columns in Section 4 are intentionally empty. A case only counts as passed after you have done it and written down what you saw.

## 3. Defects found by testing and fixed

| # | Found by | Problem | Fix |
|---|---|---|---|
| 1 | Volume probe | Orders list was silently cut at 1,000 rows and the count label looked like the full total | List limit made explicit; screen says "Showing the newest 1000 orders - use the search or the dates to narrow the list"; customer history says its totals are incomplete when cut |
| 2 | Data integrity check design | Demo data changed stock without stock-history lines, so the history did not explain the stock | Demo loader now writes "Initial stock" and "Sold on order #N" history lines |
| 3 | Error-handling checks | Text with hidden characters (line breaks, tabs, zero-width, bidi override) could be saved in single-line fields | `TextRules` refuses them with a clear message |
| 4 | Manual testing, Phase 15 | Duplicate stray `SupplierDao.java` outside the package caused a build failure | File removed; build uses 78 (later 90) sources |

## 5. Known limitations (not defects)

- One user on one computer; the database is a single local SQLite file.
- Deactivating a user who is currently logged in does not log them out until they log out themselves.
- Lists refresh when you open a tab, not live while you stay on it.
- No lockout after repeated failed logins.
- No tax calculation.
- The default admin password is documented and should be changed on real use.
- The Orders list shows at most the newest 1,000 orders (a message tells you when this happens).
- No backup feature. Copy `data/bms.db` yourself while the app is closed.
- No Settings screen: business name, currency symbol and default low-stock level can only be changed in the database.
- Accounts and roles are managed inside the Employees tab (there is no separate Users tab).
- The scripted screen checks used during development are not part of this repository.
